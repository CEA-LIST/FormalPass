# The *RISCVmirToSMTvec.cpp* pass
This pass extends the **RISCVmirToSMTfctCallLoopBound.cpp** by adding vector memory access detection and counting mechanisms.
This pass attributes unit costs to vector memory instructions (similar to scalar memory instruction counting) but it also (over-) approximates the number of elements accessed by each vector instructions by considering the vector length `vl`, to be `VLMAX`. `VLMAX` depends (among other parameters) on `VLEN`, which is a fixed hardware parameter dictated by the target architecture and `SEW`(selected element width). 
`VLEN` is a configurable parameter in this pass. 

```
(assert (= mvu_25_25 (ite t_25_25 5 0)))
(assert (= mv_25_25 (ite t_25_25 320 0)))

```
For instance, the `mvu` counter of basic block `bb25` indicates that 5 vector memory instructions are executed if transition `t_25_25` is taken.
The `mv` counter, on the other hand, shows that the total number of memory elements accessed by these 5 vector instructions combinded amount to 320 elements (as if they were scalar instructions) if  `t_25_25` is taken. These numbers were obtained by compiling **fft.c** with the new pass using  this configuration: `fft-size (n) = 128` and `VLEN=2048`. `bb25` belongs to the `stockham` function.

This is corroborated by the traces generated by this pass:


To use the new pass, make sure to pass the following compilation flag to your  `llc` command line: `-smt-generation-vec`.
